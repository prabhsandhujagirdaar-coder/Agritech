# AgriChain AI — Known Limitations & System Scope

This document provides transparent technical disclosures regarding current architectural scope, simulated vs real-hardware implementations, and ongoing engineering milestones.

---

## 1. Thermal Spoilage-Risk Estimation: Rule-Based Implementation

- **Current State**: The active spoilage-risk estimator (`backend/app/services/simulation_engine.py`) calculates spoilage probabilities using **cold-chain bounded deterministic rules** combined with a rolling 24-step sequence buffer (reefer temperature excursions >8°C, relative humidity condensation >95%, and traffic delay hours).
- **Disclosure**: While an experimental LSTM sequence model structure is scaffolded, the currently operational engine is **rule-based and deterministic**, not an externally trained PyTorch/TensorFlow LSTM model.

---

## 2. Persistence Model: Active JSON State Ledger

- **Current State**: AgriChain AI currently runs on an **atomic file-based JSON state ledger** (`backend/app/db/.persisted_session.json`).
- **Disclosure**:
  - The PostgreSQL / PostGIS migration suite (`database/migrations/`) is implemented and tested.
  - However, in standard local development and demonstration environments, PostgreSQL 16 / PostGIS 3.4 is **offline by default** (`DATABASE_ENABLED=false`).
  - All shipments, facility suitability scores, inventory, and simulation records are reliably stored in the local JSON state ledger, which survives backend restarts.

---

## 3. Vehicle Telemetry: Virtual Simulation vs Real Hardware

- **Current State**: The Simulation Studio generates **synthetic, mathematically interpolated vehicle movement** along real OSRM highway coordinates (WGS84 EPSG:4326).
- **Disclosure**:
  - Simulated vehicle telemetry points (`SNS-SIM-DEMO`) are generated by server-side tick loops and polyline interpolation.
  - They represent virtual demonstration hardware, not real physical GPS/OBD-II transponders.
  - When real IoT hardware is integrated via WebSocket `/api/v1/ws/shipments`, the data provenance tag switches from `data_source: simulation` to `data_source: hardware_gps`.

---

## 4. Mobile Client Development Status (`apps/mobile`)

- **Current State**: The Flutter application (`apps/mobile`) contains functional UI screens, shipment list cards, and tracking views.
- **Disclosure**:
  - The mobile app is an **early MVP / prototype scaffold**.
  - Primary multi-role exchange workflows (Farmer, Dealer, Buyer, Logistics, Admin) are fully accessible via the Next.js 14 Web Portal (`apps/web`).
  - Production Google Play deployment, native camera driver integration, and background BLE temperature logger sync remain under active roadmap development.

---

## 5. Offline Routing Fallbacks

- **Current State**: High-accuracy road routes are computed using public OSRM highway routing services.
- **Disclosure**: If public OSRM servers are unreachable or the environment has no internet connectivity, the system automatically falls back to an internal **calibrated multi-waypoint corridor fallback** (`routing_service.py`), ensuring uninterrupted map visualization and distance estimation.
